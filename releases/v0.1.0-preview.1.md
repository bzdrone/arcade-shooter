# Arcade Shooter v0.1.0-preview.1

A first preview of an editable MakeCode Arcade soldier game. Play a small 2v2 match, then experiment with weapon settings in Blocks or TypeScript.

## Start here

1. Download **arcade-shooter.png** from this release's assets. Use the original file, not a screenshot or converted image.
2. Open https://arcade.makecode.com/ and drag the PNG onto the page, or choose **Import → Import File**.
3. Press Play if needed. Use the arrow keys to move and **Space / A** to shoot along your last movement direction.

No installation, Git checkout, or source assembly is required. GitHub's automatic "Source code" archives are for authors; learners should download the PNG instead.

## Included

- **arcade-shooter.png** — the game with embedded editable source, custom Blocks, and tilemap assets.

The handouts are separate downloads, not embedded in the game PNG.

## The game

You and one blue bot face two red soldiers. Your soldier has a white helmet stripe. First team to ten eliminations wins.

All soldiers share health and weapon rules. Only bullets cause damage, friendly fire is off, cover blocks shots, and eliminated soldiers return after at least five seconds at an available team spawn point. Weapon changes apply to both teams.

## Preview status

- Arcade compilation and 28 host-side rule/navigation tests passed.
- Real-simulator checks covered combat, cover routing, respawn timing, occupied spawn points, both match endings, and button restart. Ending checks seeded the score at nine; they were not complete natural matches.
- The exact PNG passed fresh local and hosted editor import, custom Blocks checks, and tilemap-editor opening. Local checks also verified an edited Blocks setting took effect after recompilation.
- The project owner playtested the game and reported that it played well.

**Learner evaluation is still pending.** This is a learner-test candidate, not a validated lesson. Bot behavior is intentionally simple; match balance and teaching effectiveness are not established by automated tests.

After editing settings, **stop and start** the simulator to recompile. Fast restart can reuse old code. Keep the original PNG to return to the baseline.
